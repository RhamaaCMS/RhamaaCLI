Remove duplication in `rhamaa cms startapp` by extracting a shared “install into apps/ + overwrite/dry-run + optional configure” pipeline that both template and prebuilt/manifest flows use, while keeping CLI flags and routing behavior compatible.

Purpose: Reduce maintenance cost and bug surface area across multiple install modes.
Output: Refactored `startapp.py` with shared helpers, no behavior regressions for existing flags.

Key current behaviors to preserve:

- CLI entry in `startapp()` routes:
  - `--list` / `--list-templates` => prints and exits
  - `--prebuild` => `install_prebuilt_app(...)` and returns
  - `--template-url`/`--template-file` OR non-builtin `--template` => `install_template_app(...)` and returns
  - otherwise => `create_standard_app(...)`
- Prebuilt path defaults to manifest-based install (unless `--skip-config` true, which triggers “basic install without manifest” fallback).
- Built-in templates `minimal` and `wagtail` are handled via `create_standard_app(...)`.



Task 1: Introduce a shared “apps/ install” pipeline (no behavior change)rhamaa/commands/cms/startapp.py, rhamaa/utils.py Create a small, shared helper layer that normalizes the repeated steps used by BOTH the template and prebuilt flows:

- A single function (placed in `rhamaa/utils.py` or in `startapp.py` if it must stay CLI-local) that:
  - resolves `apps_dir = Path("apps")`, `app_dir = apps_dir / app_name`
  - enforces `--force` behavior consistently (if target exists and not force -> same warnings/returns as today)
  - performs “dry-run messaging” consistently (no filesystem mutations)
  - if not dry-run:
    - ensures `apps/` exists
    - removes existing `apps/<app_name>` when `--force`
    - installs content into `apps/<app_name>` from a provided “source” (either extracted template dir, extracted repo dir, or zip extraction result)

Constraints for this helper:

- Do NOT change the CLI option set or routing conditions; only refactor internals.
- Preserve existing user-facing output as much as feasible (wording can differ slightly, but semantics must match).
- Ensure no path traversal vulnerabilities are introduced when extracting/moving content into `apps/<app_name>` (e.g., guard against ZIP entries escaping the temp dir; keep extraction rooted and move only a validated directory).

This task should be primarily mechanical: move duplicated code into helpers and rewire callers with minimal logic changes.
